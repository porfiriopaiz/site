Configuring GNOME and Nautilus via gsettings on Fedora

On Fedora Linux with the GNOME desktop, hardware, interface, and file manager preferences are distributed across multiple GSettings schemas. Using gsettings from the terminal lets you inspect keys, query allowed values, monitor live changes, and script reproducible workstation setups without clicking through graphical menus.

Essential GNOME Hardware and Interface Settings

Touchpad and Input Configuration

On a portable workstation such as a Lenovo ThinkPad, enabling tap-to-click and comfortable scrolling behavior directly from the shell is often one of the first post-install adjustments.

  • Schema: org.gnome.desktop.peripherals.touchpad
# Enable tap-to-click
gsettings set org.gnome.desktop.peripherals.touchpad tap-to-click true

# Enable Natural Scrolling (reverse scroll)
gsettings set org.gnome.desktop.peripherals.touchpad natural-scroll true

# Set Two-finger scrolling
gsettings set org.gnome.desktop.peripherals.touchpad two-finger-scrolling-enabled true

Panel, Clock, and Status Indicators

GNOME refers to the top bar as the Panel and the application dock as the Dash. Interface indicators such as clock formatting and battery readouts live under org.gnome.desktop.interface, while dock extensions such as Dash to Dock use their own extension schema under org.gnome.shell.extensions.dash-to-dock.

# Show the day of the week alongside date/time
gsettings set org.gnome.desktop.interface show-datetime-day-of-week true

# Show seconds in the clock
gsettings set org.gnome.desktop.interface clock-show-seconds true

# Show battery percentage
gsettings set org.gnome.desktop.interface show-battery-percentage true

Power and Lid Behavior

Power management and sleep timeouts are controlled through the org.gnome.settings-daemon.plugins.power schema.

# Set sleep timeout on Battery (seconds, e.g., 900 = 15 mins)
gsettings set org.gnome.settings-daemon.plugins.power sleep-inactive-battery-timeout 900

# Prevent suspend when the laptop lid is closed (if plugged in)
gsettings set org.gnome.settings-daemon.plugins.power lid-close-ac-action 'nothing'

Discovering Schemas and Monitoring Changes

When configuring unfamiliar tools or extensions, you can filter available schema names and watch live property updates as you interact with GNOME Settings:

  1. Filter schemas by keyword:

    gsettings list-schemas | grep -i "power"

  2. Monitor a schema in real time while changing settings in the GUI:

    gsettings monitor org.gnome.desktop.peripherals.touchpad

Common GSettings Schemas Reference

Feature GSettings Schema
Touchpad org.gnome.desktop.peripherals.touchpad
Keyboard org.gnome.desktop.peripherals.keyboard
Interface/Fonts org.gnome.desktop.interface
Privacy/Lock org.gnome.desktop.screensaver
Window Focus org.gnome.desktop.wm.preferences

Switching Between Dark and Light Color Schemes

System-wide light and dark color scheme preferences on GNOME are controlled by the color-scheme key under org.gnome.desktop.interface.

Enable Dark Mode

gsettings set org.gnome.desktop.interface color-scheme 'prefer-dark'

Revert to Light / Default Mode

gsettings set org.gnome.desktop.interface color-scheme 'default'

Check the Active Color Scheme

gsettings get org.gnome.desktop.interface color-scheme

Toggle Color Scheme via Shell Snippet

You can toggle between 'prefer-dark' and 'default' with a short shell check:

CURRENT=$(gsettings get org.gnome.desktop.interface color-scheme)
if [ "$CURRENT" = "'prefer-dark'" ]; then
    gsettings set org.gnome.desktop.interface color-scheme 'default'
else
    gsettings set org.gnome.desktop.interface color-scheme 'prefer-dark'
fi

Configuring Nautilus Sorting and Folders First

Nautilus schema keys and sorting behavior have shifted across GNOME and GTK releases—for example, folder-first sorting is handled at the GTK FileChooser level rather than as a standalone folders-first key under org.gnome.nautilus.preferences.

Inspecting Nautilus Keys and Ranges

List available keys and current values under org.gnome.nautilus.preferences:

gsettings list-keys org.gnome.nautilus.preferences

gsettings list-recursively org.gnome.nautilus.preferences

Search across all schemas for keys matching sort or folder:

gsettings list-recursively | grep -iE "sort|folder"

Check valid enum values or ranges for a key using gsettings range:

gsettings range org.gnome.nautilus.preferences default-sort-order

gsettings range org.gtk.Settings.FileChooser sort-directories-first

gsettings range org.gtk.gtk4.Settings.FileChooser sort-directories-first

Sorting by Type and Ascending Order

Set default sorting by type and keep ascending order enabled:

gsettings set org.gnome.nautilus.preferences default-sort-order 'type'

gsettings set org.gnome.nautilus.preferences default-sort-in-reverse-order false

Enforcing Folders First via GSettings and dconf

Set sort-directories-first across GTK 3 and GTK 4 FileChooser schemas:

# GTK3 FileChooser
gsettings set org.gtk.Settings.FileChooser sort-directories-first true

# GTK4 FileChooser (used by modern GNOME/Nautilus)
gsettings set org.gtk.gtk4.Settings.FileChooser sort-directories-first true

If a schema is not exposed through gsettings in your session, write the underlying keys directly with dconf or search for matching keys:

dconf write /org/gtk/settings/file-chooser/sort-directories-first true

dconf write /org/gtk/gtk4/settings/file-chooser/sort-directories-first true

gsettings list-recursively | grep -i "sort-directories"

Restarting Nautilus and Clearing Cached Metadata

To apply the changes immediately and clear per-directory overrides stored in GVfs metadata:

# Terminate Nautilus process
nautilus -q

# Remove saved per-directory metadata overrides
rm -rf ~/.local/share/gvfs-metadata

Finishing Touches

Keeping GNOME and Nautilus settings in gsettings and dconf commands makes it straightforward to reproduce your exact desktop layout, input behavior, and file sorting preferences across fresh Fedora installations.
